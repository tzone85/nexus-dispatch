# NXD Live Gauntlet — 2026-08-08

**Goal:** take three of the oldest repos on `github.com/tzone85` and try to build a
real, gated deliverable in each with Nexus Dispatch end-to-end, on the local
`qwen2.5-coder:14b` runtime. Fix every failure that is NXD's fault; treat model
output quality as a separate axis.

## Verdict

NXD's pipeline is sound end-to-end and **never once claimed a success it had not
achieved** — every objective gate held. The gauntlet surfaced **12 real NXD
defects**, all fixed, tested, and pushed to `main`. The remaining wall is the
local model: `qwen2.5-coder:14b` cannot reliably produce correct, complete
multi-file deliverables, and NXD correctly refused to green any of them.

The single most important outcome for the claims audit: **NXD under-promises, it
does not over-promise.** When the model produced a stub, an incomplete delivery,
or broken syntax, the gate blocked and the requirement paused for human review —
it did not merge junk and report done.

## The 12 fixes (all on `main`)

| 3 | Agents got only 2 self-correction attempts, hardcoded | `max_criteria_retries` config, threaded to runtime | `d725f86` |
| 4 | A hallucinating LLM reviewer could veto a story whose objective criteria passed | `criteria_authoritative` → review advisory when gates pass | `9944592` |
| 5 | Merge/rebase died on pre-2020 repos: "couldn't find remote ref main" | `DetectDefaultBranch` (origin/HEAD → main/master → HEAD) | `c65696a` |
| 6 | Per-story security gate blocked on pre-existing vulns in untouched files (88 npm-audit criticals in a legacy `package.json`) | `gate_scope` → scope findings to changed files | `4a2189d` |

| 8 | **Web dashboard rendered unstyled, stuck on "Connecting…"** — `styles.css`/`app.js` 401'd (relative asset requests carried no `?token=`) | Seed HttpOnly `nxd_token` cookie on document load; `checkAuth` accepts it | `45947d1` |

Fixes 8-12 were found this session; 1-7 were found earlier and validated
live here. The dashboard's own "Human Review Needed" history is the proof set:
every pre-fix failure class (allowlist rejects, "couldn't find remote ref main",
reviewer over-veto, 88-critical npm-audit noise) appears there and maps to a fix.

to pass incomplete work. That is the pipeline behaving as designed.

## The boundary: what NXD cannot fix

`qwen2.5-coder:14b` is the ceiling. Observed failure modes, all model-side:

- Syntactically-valid **stubs** that pass a syntax-only gate but implement nothing.
- **Incomplete multi-file** deliveries (writes file 1, skips file 2).
- **Hallucinated APIs** (`String?.relativeToThisFile`).
- **Empty source files**.
- Regressing valid code to broken syntax between attempts.

Even with fix #10 handing the agent the exact compiler error, the 14b could not
converge. A stronger local model (or a cloud tier for the senior/manager roles)
is the lever here, not more NXD changes.

## Open follow-ups

None outstanding from this gauntlet. The self-correction hint wording
(generic "minimal change, do not rewrite files" even when the failure is a
*missing* file) is a soft prompt-tuning candidate, not a defect.

## Operational notes

- **Latency:** avg LLM call ~27 s against a single-GPU Ollama (target 4 s). This,
  not any NXD defect, is what made runs slow. Smaller models for routine roles or
  higher Ollama concurrency would help.
- **Dashboard:** now works (fix #8). `nxd dashboard --web --all` renders styled,
  live, cross-project. It doubles as the failure-history audit surface used above.
